`tech.md` в корне репозитория, единственный источник истины. Прочитай его целиком перед первым изменением кода и подчиняйся ему дословно. Расхождение между этим файлом и `tech.md` решается в пользу `tech.md`.

## Трек

Трек один, размер проекта S. Задачи в секции `## Задачи` файла `tech.md`, порядок обязателен. Задача 4, страница нормативов одной дистанции, эталонная вертикаль: задачи 5 и 7 повторяют её структуру.

Задачи не начинаются, пока чек-лист `## Скелет` не зелёный целиком.

## Контракты

Нужного типа, поля или узла шкалы нет в `tech.md`: правь ядро на месте тем же PR и допиши строку в changelog с бампом версии. Код с выдуманным типом не пиши.

Правка задевает `RANK_POINTS`, `RANK_ORDER` или форму `Edition`: СТОП, выдай блок `CONTRACT GAP` из `tech.md` и жди решения владельца. Такая правка переписывает уже показанные пользователю очки.

## Границы

- Числа нормативов берутся только из текста приказа Минспорта № 1092. Сторонние сайты в датасет не попадают.
- Цветовых значений вне `globals.css` не существует. В модулях только `var(--role)`.
- Любое числовое значение рендерится моноширинным шрифтом с `font-variant-numeric: tabular-nums`.
- Компонент в `src/ui/` не импортирует из `domain/` и `features/`.
- Серверного рантайма нет. Всё, что ломает `output: 'export'`, запрещено: серверные экшены, роут-хендлеры, ISR, middleware, оптимизатор изображений, динамический роут без `generateStaticParams`.
- `any` запрещён, включая `as any`.

## Работа

Одна задача за раз, сфокусированный дифф. Не расширяй объём задачи по ходу.

Тест выводится из критериев приёмки задачи, не из реализации.

Коммить маленькими логическими коммитами по ходу работы, не одним в конце. Формат `type(scope): summary`, `type` из `feat|fix|test|refactor|chore|docs`, английский, императив, со строчной, без точки.
