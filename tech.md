## Проект

Веб-приложение для просмотра разрядных нормативов ЕВСК по плаванию и расчёта очков разряда.

Две функции, больше ничего:

1. **Просмотр нормативов.** Главная страница: пререндеренные таблицы ЕВСК по дистанциям, стилям, бассейнам и полу.
2. **Калькулятор.** Дополнительная страница `/kalkulyator/`. Пользователь выбирает бассейн, пол, стиль и дистанцию одним тапом и набирает время. Получает выполненный разряд, остаток секунд до следующей ступени и очки разряда по шкале 0–1000, всё на одном экране без скролла.

Аудитория: спортсмены, родители, тренеры. Регистрации нет, аккаунтов нет, данные пользователя не хранятся.

Цель итерации: проверить единственную гипотезу продукта, что непрерывное число мотивирует сильнее дискретной ступени. Всё, что требует аккаунта, журнала результатов, импорта протоколов или оплаты, вне объёма.

### Ядро предметной логики

Очки разряда натягивают непрерывную шкалу 0–1000 на дискретную сетку ЕВСК. Каждый разряд получает фиксированную отметку. Между отметками результат считается по кубической зависимости, как в системе очков World Aquatics.

Формула для времени `T` между нормативом нижней ступени `T1` (медленнее, очки `S1`) и верхней `T2` (быстрее, очки `S2`):

```
S = S1 + (S2 - S1) * ((T1/T)^3 - 1) / ((T1/T2)^3 - 1)
```

На узлах формула даёт ровно узловое значение. Внутри отрезка растёт монотонно. Ниже нижней ступени и выше верхней шкала продолжается экстраполяцией той же кривой.

Шкала линейна по `x = 1/T³`, поэтому отрезок между двумя ступенями, это прямая, а вся кривая, это ломаная по узлам. Выше самой быстрой ступени продолжается верхний отрезок. Ниже самой медленной ломаная идёт до неявного узла «бесконечное время, ноль очков». Продолжать вместо этого нижний отрезок нельзя: он пересекает ноль на реальном времени новичка, 100 секунд на 50 м вольным дают минус 2 очка, и ломает инвариант положительности. Неявный узел оставляет кривую положительной и строго монотонной на всей области, формула остаётся той же, исключения в коде нет.

Очки, это внутренняя метрика продукта, а не официальный статус. Разряд присваивает спортшкола или орган власти по протоколу старта нужного ранга. Интерфейс обязан показывать оба слоя и не выдавать очки за присвоенный разряд.

## Стек

Postgres и Drizzle из первоначального выбора выкинуты: статический экспорт не имеет серверного рантайма, а нормативы, это неизменяемый датасет в репозитории. Next.js App Router с `output: 'export'` даёт пререндер всех страниц нормативов для поиска и один клиентский калькулятор. Vitest с fast-check закрывает единственную сложную часть, чистую функцию очков.

### Обязательная конфигурация Next.js

`next.config.ts`:

```ts
import type { NextConfig } from 'next';

const config: NextConfig = {
  output: 'export',
  trailingSlash: true,
  images: { unoptimized: true },
  reactStrictMode: true,
};

export default config;
```

`trailingSlash: true` обязателен: статический хостинг раздаёт каталоги, без него вложенные роуты отдают 404. `images.unoptimized` обязателен, оптимизатор изображений требует рантайма. Любой динамический роут обязан экспортировать `generateStaticParams`, иначе сборка падает.

## Схема данных

БД нет, поэтому схема, это форма статического датасета. Времена нормативов **не зависят от возраста**. Возраст определяет только то, какие ступени вообще доступны спортсмену. Это единственное место, где возраст участвует в расчёте.

`src/domain/standards/types.ts`:

```ts
export type Pool = 'LCM' | 'SCM';                    // 50 м | 25 м
export type Sex = 'M' | 'F';
export type Stroke = 'FREE' | 'BACK' | 'BREAST' | 'FLY' | 'MEDLEY';
export type Distance = 50 | 100 | 200 | 400 | 800 | 1500;

export type Rank =
  | 'YOUTH_3' | 'YOUTH_2' | 'YOUTH_1'
  | 'ADULT_3' | 'ADULT_2' | 'ADULT_1'
  | 'CMS' | 'MS' | 'MSMK';

/** Один норматив: одна ступень на одном событии. Время в секундах. */
export type StandardRow = {
  pool: Pool;
  sex: Sex;
  stroke: Stroke;
  distance: Distance;
  /** Ступень отсутствует в приказе, значит ключа нет. Прочерк не кодируется нулём. */
  times: Partial<Record<Rank, number>>;
};

export type Edition = {
  /** Дата вступления в силу в ISO, она же идентификатор. */
  id: string;
  /** Точная ссылка на приказ, показывается в интерфейсе. */
  order: string;
  effectiveFrom: string;
  /** null, значит редакция действующая. */
  effectiveTo: string | null;
  rows: StandardRow[];
};

export type PointsResult = {
  /** Целое, обычно 0..1000, за границами шкалы возможен выход. */
  points: number;
  /** Выполненная ступень, null если результат медленнее III юношеского. */
  achievedRank: Rank | null;
  /** Следующая ступень по времени, null если результат быстрее МСМК. Возраст её не фильтрует. */
  nextRank: Rank | null;
  /** Сколько секунд срезать до nextRank, null если nextRank отсутствует. */
  gapSeconds: number | null;
  /** Выполненные по времени ступени, которые возраст не даёт присвоить. Порядок RANK_ORDER. */
  blockedByAge: Rank[];
  editionId: string;
};
```

Ключ поиска строки: `` `${pool}|${sex}|${stroke}|${distance}` ``. `registry.ts` строит из массива `rows` неизменяемую `Map` один раз на модуль. Это единственная замена индексу БД.

### Zod-схема датасета

`src/domain/standards/schema.ts`. Валидирует датасет в тесте и в шаге сборки. Задача схемы, поймать опечатку в переписанной вручную таблице.

```ts
import { z } from 'zod';

const rankSchema = z.enum([
  'YOUTH_3', 'YOUTH_2', 'YOUTH_1',
  'ADULT_3', 'ADULT_2', 'ADULT_1',
  'CMS', 'MS', 'MSMK',
]);

export const standardRowSchema = z.object({
  pool: z.enum(['LCM', 'SCM']),
  sex: z.enum(['M', 'F']),
  stroke: z.enum(['FREE', 'BACK', 'BREAST', 'FLY', 'MEDLEY']),
  distance: z.union([
    z.literal(50), z.literal(100), z.literal(200),
    z.literal(400), z.literal(800), z.literal(1500),
  ]),
  // partialRecord, а не record: в Zod 4 record по enum-ключу требует все ключи.
  times: z.partialRecord(rankSchema, z.number().positive().max(3600)),
});

export const editionSchema = z.object({
  id: z.string().regex(/^\d{4}-\d{2}-\d{2}$/),
  order: z.string().min(10),
  effectiveFrom: z.string().regex(/^\d{4}-\d{2}-\d{2}$/),
  effectiveTo: z.string().regex(/^\d{4}-\d{2}-\d{2}$/).nullable(),
  rows: z.array(standardRowSchema).min(1),
});
```

### Источник чисел

Единственный допустимый источник нормативов, текст приказа Минспорта России от 6 ноября 2024 г. № 1092, действует с 26 ноября 2024 года, опубликован на minsport.gov.ru в разделе ЕВСК по виду спорта «плавание».

Числа со сторонних сайтов в датасет не попадают. Каждая строка сверяется с приказом. В `editions/2024-11-26/index.ts` фиксируется точная ссылка на источник. На экране она не показывается: упоминание приказа снято из интерфейса целиком, источник живёт в коде.

## UI-примитивы

Готовая библиотека не берётся. Дизайн-система строго монохромная, любую готовую пришлось бы переопределять целиком, а десять примитивов на CSS Modules дешевле переопределения. --canvas --surface --inset --hover --hairline --border --slate --softened --ink

Вне зеркала объявлены две константы, `--qr-paper` и `--qr-ink`, одинаковые в обоих ликах: сканер не обязан читать инвертированный QR-код, поэтому его модули остаются обсидиановыми на титановой плашке. Больше исключений из переключения нет.

ОБСИДИАН, основной лик: canvas `#0D0D0D`, surface `#1A1A1A`, inset `#121212`, hover `#212121`, hairline `#2E2E2E`, border `#6B6B6B`, slate `#8A8A8A`, softened `#D1D1D1`, ink `#FAFAFA`. Значения те же, что на fina.borozdov.ru: приложения бренда не отличаются оттенком.

ТИТАН, светлый лик: canvas `#FAFAFA`, surface `#FFFFFF`, inset `#ECECEC`, hover `#F2F2F2`, hairline `#E4E4E4`, border `#8A8A8A`, slate `#6B6B6B`, softened `#3D3D3D`, ink `#0D0D0D`.

Роли границ: `hairline` рисует все декоративные рамки, чипов, сегментов, полей и карточек; `border` только интерактивные, кнопку автора и ховер.

Жёсткие правила стиля, нарушение блокирует мерж:

- цветовых значений вне `globals.css` не существует, в модулях только `var(--role)`;
- тени не используются, глубина строится линиями в один пиксель и ступенями поверхности;
- акцент ставится только инверсией заливки, не цветом;
- заголовки прописными с отрицательным трекингом, лейблы прописными с положительным трекингом;
- любое числовое значение, время, очки, остаток, дата, рендерится моноширинным шрифтом с `font-variant-numeric: tabular-nums`;
- полностью круглых элементов нет, кроме точек-индикаторов;
- эмодзи в интерфейсе нет;
- лики не смешиваются в пределах страницы;
- системная тема читается один раз при первом визите, дальше лик определяется сохранённым выбором;
- `prefers-reduced-motion` уважается;
- приложение, это один экран: `body` не скроллится, страница раскладывает себя внутри высоты, вёрстка одна мобильная колонка и на телефоне, и на ПК; скроллится только `/kitchen-sink`.

## Конвенции кода

- Язык коммитов, PR, комментариев и имён в коде, английский. Пользовательские строки интерфейса, русский.
- Формат коммита Conventional Commits, всегда: `type(scope): summary`. `type` из закрытого набора `feat|fix|test|refactor|chore|docs`. `summary` в императиве, со строчной буквы, без точки, до 50 символов. Тело только чтобы объяснить почему, не что.
- Сессия коммитит сама по ходу работы, маленькими логическими коммитами после каждого осмысленного шага, а не одним коммитом в конце. Каждый коммит по возможности проходит тайпчек.
- PR: заголовок краткий. Тело, что делает слайс, какие контракты затрагивает, чем покрыт.
- Комментарии объясняют почему, не пересказывают очевидный код. Закомментированный код в PR не остаётся.
- Проза в документации и PR: активный залог, императив, без филлеров, без em-dash.
- `any` запрещён, включая `as any`. Расширение типа только через явный тип-гард.
- Именованные экспорты везде. Исключение, файлы `page.tsx`, `layout.tsx`, `not-found.tsx`, где Next.js требует default export.
- Инлайновых стилей нет. Только CSS Modules плюс токены ролей.
- Компонент в `ui/` не импортирует из `domain/` и `features/`.
- Время внутри домена, всегда число секунд. Строка `mm:ss.hh` существует только на границе ввода и вывода, преобразуется в `domain/points/time.ts`.

## Тесты

Слайс мёрджится только с тестами. Главная ловушка: написать код, затем написать тесты, подтверждающие, что код делает то, что делает, вместе с багами. Тесты зелёные и не проверяют ничего.

Правило: **тест выводится из критериев приёмки задачи, не из реализации.** Тест кодирует контракт.

Обязательные типы, адаптированные под статический сайт без рантайма:

- **Контрактные на стыках.** Стык здесь один и он самый ценный, датасет нормативов против Zod-схемы и инвариантов. `dataset.test.ts` проверяет: датасет проходит `editionSchema`; ключ `pool|sex|stroke|distance` уникален; внутри каждой строки времена строго убывают по `RANK_ORDER` от медленной ступени к быстрой; отсутствующая ступень выражена отсутствием ключа, не нулём; покрыто ожидаемое множество событий для каждого бассейна и обоих полов, общее для двух бассейнов плюс комплекс 100 метров, который плавают только в короткой воде. Опечатка в переписанной таблице падает здесь, а не у пользователя.
- **Идемпотентность.** Обработчиков нет, поэтому проверяется её аналог для чистой функции: `calculate` детерминирована, повторный вызов с тем же входом даёт тот же результат, входные структуры не мутируются.
- **Путь ошибки.** Невалидная строка времени. Время быстрее МСМК, экстраполяция вверх. Время медленнее III юношеского, экстраполяция вниз. Отсутствующий норматив на ступени, прочерк в приказе, ступень пропускается и очки считаются от следующей существующей. Событие, которого нет в датасете. Возраст ниже минимального для выполненной ступени, ступень уходит в `blockedByAge`.
- **Property-based на чистой доменной логике.** fast-check на `calculate`. Инварианты: результат не убывает при убывании времени; на каждом узле шкалы значение равно ровно `RANK_POINTS[rank]` с точностью до целого; очки не отрицательны для любого положительного времени, кривая строго положительна и округляется до нуля только за пределами мыслимого результата; `gapSeconds` неотрицателен, когда `nextRank` существует.

### 3. Функция очков

**Цель.** `calculate.ts`, `scale.ts`, `time.ts`. Ядро продукта.

**Контракты.** Реализует `PointsResult`, `RANK_POINTS`, `RANK_ORDER`.

**Критерии приёмки.**

- Внутри отрезка применяется формула из раздела «Ядро предметной логики».

**Тесты.** Property-based на `calculate`, четыре инварианта из раздела «Тесты». Табличные тесты на каждый путь ошибки. Тест детерминированности и отсутствия мутации входа. ### 6. Калькулятор

**Цель.** Страница `/kalkulyator/`. Выбор параметров одним тапом, ввод времени, вывод разряда, остатка до следующей ступени, очков и шкалы, всё в одном экране.

**Контракты.** Читает `PointsResult`, `Rank`, `StandardRow`. Новых не вводит.

**Примитивы.** `TimeInput`, `Segmented`, `Chips`, `ScaleBar`.

**Критерии приёмки.**
- Плашка результата рендерится всегда и входит в экран телефона вместе с формой. Иерархия сверху вниз: полное название ступени прописными (`I спортивный`, `Кандидат в мастера спорта`), остаток до следующей ступени в секундах с двумя знаками моноширинно, очки мельче всего. Ниже III юношеского плашка говорит «Разряда нет».
- Возраст не спрашивается. `calculate` вызывается без `age`, `blockedByAge` пуст.
- Время вводится тремя полями `м : с . сот` с автопереходом после двух цифр или одной быстрой строкой в любой записи; последний набор побеждает и очищает другой. Результат появляется на первый читаемый символ: `58` уже даёт ступень.
- `ScaleBar` показывает позицию результата и все девять узлов отдельным блоком под плашкой; на высоте ниже 600px шкала скрывается, плашка нет.
- Под очками стоят нормативы соседних ступеней: время выполненной и время следующей, медленная слева. Ступень, у которой в приказе прочерк, пропускается.
- Пояснений на странице нет: ни заголовка, ни дисклеймера, ни источника.
- Расчёт идёт на клиенте, страница остаётся статической.
- Невалидное время не роняет страницу, поле помечается `invalid`, плашка показывает причину вместо результата.
- Состояние формы отражается в query-параметрах, чтобы результат можно было отправить ссылкой. Ссылка со старым `age` читается, параметр игнорируется.

**Тесты.** Тест восстановления состояния из query-параметров и обратно. Рендер-тест: для проверочной строки вольного стиля показаны `I спортивный`, остаток `1.25` до КМС и `600` очков. Тест частичного ввода: `45` даёт ступень сразу. Тест невалидного ввода: плашка показывает причину, поле помечено.

### 9. Оффлайн, шеринг и поисковая разметка

**Цель.** Приложение живёт как приложение: работает без сети, ставится на домашний экран, отдаёт результат картинкой и ссылкой, показывает поисковикам карточку и разметку.

**Контракты.** Новых доменных не вводит. Пункт «Сервис-воркер и офлайн-режим вне объёма S» из задачи 8 отменён: оффлайн, это главное, чего ждут от установленного приложения.

**Примитивы.** `Toast`, `JsonLd`.

**Критерии приёмки.**
- После первой загрузки приложение открывается при выключенной сети, включая адрес, на который читатель ещё не заходил.
- Новая сборка не перезагружает страницу сама: показывается тост, перезагрузка по кнопке.
- Баннер установки предлагается один раз и запоминает отказ; на iOS вместо кнопки инструкция.
- Кнопка результата отдаёт картинку 1080×1080 и ссылку, которая открывает тот же результат. Где системного шеринга нет, картинка скачивается.
- Кнопка в шапке делится самим приложением, без системного шеринга адрес копируется.
- У каждой страницы есть Open Graph, Twitter-карточка и канонический адрес; главная и калькулятор несут разметку Schema.org.
- Экранная клавиатура не выталкивает плашку результата: подвал и переключатель разделов уходят, высота считается по `visualViewport`.
- Ни один сторонний скрипт не грузится, пока `METRIKA_ID` равен `null`.

**Тесты.** `sw.test.ts`: предкэш совпадает с маршрутами оболочки, `skipWaiting` не вызывается при установке. `install.test.ts`: скриншоты, ярлыки, картинка ссылки и стартовые экраны существуют и тех размеров, что объявлены. `shareCard.test.ts`: содержимое карточки для проверочной строки. `jsonLd.test.ts`: разметка валидна и ссылается только на свой origin. `keyboard.test.ts` и `install.ts`: чистые правила. `analytics.test.ts`: при `null` ничего не отправляется.

### 10. QR-визитка

**Цель.** Экран, который показывают с чужого телефона: код на адрес сайта, чтобы поделиться приложением, не диктуя адрес.

**Контракты.** Новых доменных не вводит. Ядро тронуто дважды: `globals.css` получил `--qr-paper` и `--qr-ink`, корневой `layout.tsx` отдал хром группе `(shell)`.

**Критерии приёмки.**
- `/qr/` собирается в `out/qr/index.html` и открывается напрямую.
- Камера читает код и открывает канонический адрес главной.
- Страница, это отдельный экран: ни шапки, ни переключателя разделов, ни подвала, свои кнопки «назад» и «лик» по углам.
- Иконка QR в шапке ведёт на страницу из любого раздела.
- Код одинаков в обоих ликах, обсидиановые модули на титановой плашке.
- Печать в центре перекрывает меньше трети кода, уровень коррекции H.
- На отрисовку кода не грузится ни одного клиентского скрипта: SVG приходит из сборки.
- Страница не попадает ни в карту сайта, ни в индекс, и лежит в предкэше воркера.
- 404 не теряет хром, хотя корневой layout стал голым.

**Тесты.** `qr.test.ts`: три глаза по углам, печать по центру, ни один модуль данных не уходит под глаз или под печать, повторный вызов даёт тот же план. `QrScreen.test.tsx`: адрес в чипе, литера печати, путь назад, теги. `qr/page.test.tsx`: канонический адрес и `noindex`. `sw.test.ts` и `sitemap.test.ts` расширены на `/qr/`.


### 11. Справочный слой и поиск

**Цель.** Дать запросу вида «норматив КМС 100 брасс 25 метров» адрес, на который можно прийти, не трогая одноэкранное приложение.

**Контракты.** Новых доменных не вводит. Ядро тронуто трижды: правило одного экрана в `globals.css` привязано к `data-screen`, `theme.ts` получил `TITAN_CANVAS`, `SiteShell` получил проп `flow`. `RANK_POINTS`, `RANK_ORDER` и форма `Edition` не тронуты.

**Критерии приёмки.**
- Экспорт пишет страницу на каждое событие `listEvents()`, указатель `/normativy/` и разбор `/razryady/`; карта сайта перечисляет ровно их и две страницы приложения.
- На каждой странице сборки ровно один `h1`, и он содержит слова, которыми событие ищут, а не сокращения чипов.
- Оба пола видны на странице события одновременно, ни одно время не лежит под `hidden`.
- Абзацы страницы события считаются из датасета и не совпадают ни у каких двух событий.
- Страниц без входящей ссылки в `out/` нет, кроме 404 и `/kitchen-sink/`.
- На `375×667` и `375×812` в обоих ликах страницы приложения по-прежнему равны высоте окна, справочные прокручиваются до подвала.
- 404 отдаёт ровно один тег `robots`, и это `noindex`.
- В сборке есть `favicon.ico`, `icon.svg` и `apple-touch-icon.png` 180×180 без альфы; в манифесте ровно одна иконка `maskable` и она отдельным файлом.
- `theme-color` объявлен двумя тегами с `media`, цвета совпадают с `--canvas` двух ликов.
- Справочная страница открывается при остановленном сервере после того, как была прочитана.

**Тесты.** `standardsCopy.test.ts`: числа абзацев читаются обратно из датасета, ни один абзац не повторяется. `ranksCopy.test.ts`: разница бассейнов сходится с двумя временами, из которых считается, и падает, если нижняя ступень когда-нибудь станет согласованной. `labels.test.ts`: три формы русского множественного числа, включая одиннадцать и двенадцать. `normativy/[...]/page.test.tsx`: `generateStaticParams` равен перечню событий, обе колонки полов, один `h1`, ссылки на соседей и калькулятор. `normativy/page.test.tsx`: указатель ссылается на каждое событие. `razryady/page.test.tsx`: девять ступеней с возрастом. `install.test.ts` расширен на новые иконки и второй лик, `sitemap.test.ts` на весь слой, `sw.test.ts` на префикс рантайм-кэша.

**Осталось владельцу.** Ни одно из этого не выдумывается кодом: публикация сайта, отдельная запись поддомена в Вебмастере с подтверждением файлом и режимом «Не выполнять JS», номер счётчика в `analytics.ts`, ключ IndexNow.
